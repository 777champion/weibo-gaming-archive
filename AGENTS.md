
# Weibo Gaming Archive — Project Instructions

## 1. Project Overview

Weibo Gaming Archive is a fan-made archive dedicated to the Identity V division of Weibo Gaming (WBG), also known as Beijing WBG.

The website aims to organize, preserve, and present information about the team's players, history, matches, achievements, and related content.

This is an independent fan project and is not an official website of Weibo Gaming or Identity V League (IVL).

## 2. Project Goals

- Build a comprehensive archive covering all relevant aspects of Beijing WBG's Identity V division.
- Organize historical and current information in a clear and accessible structure.
- Provide an intuitive browsing experience.
- Maintain a consistent visual identity across all pages.
- Make the website easy to maintain and expand.

## 3. Language

- Traditional Chinese (繁體中文) is the primary interface language.
- Use English for technical identifiers, filenames, code, and appropriate terminology.
- Use Taiwan Traditional Chinese conventions.
- Keep wording consistent throughout the website.

## 4. Design Direction

- Theme: Dark.
- Visual style: Modern, editorial, immersive, and archive-oriented.
- The interface should feel like a carefully curated esports archive.
- Use a consistent color palette, typography, spacing, and component system.
- Prioritize readability and clear information hierarchy.
- Avoid excessive decoration, unnecessary animations, and cluttered layouts.
- Use responsive layouts for desktop, tablet, and mobile devices.

## 5. Website Scope

The project has comprehensive coverage (All).

Potential content categories include:

- Team introduction and history.
- Player profiles and career information.
- Rosters and lineup changes.
- Match records and tournament results.
- Season archives.
- Achievements and milestones.
- Notable events and historical timelines.
- Media and related materials.

Do not arbitrarily exclude relevant categories simply to simplify implementation.

## 6. Information Accuracy

- Never fabricate player information, match results, dates, statistics, or historical events.
- Distinguish verified information from uncertain information.
- Preserve historical context when presenting older records.
- Use reliable sources whenever possible.
- Provide source references for factual information when available.
- Do not present fan speculation as confirmed facts.

## 7. Technical Requirements

- The website must be compatible with GitHub Pages.
- Use relative or correctly configured asset paths so pages work after deployment.
- Ensure navigation and internal links work correctly.
- Keep code organized, readable, and maintainable.
- Avoid unnecessary dependencies.
- Ensure the website works on modern desktop and mobile browsers.
- Optimize images and other assets for reasonable loading performance.

## 8. Responsive Design

- Desktop is the primary design target.
- Tablet and mobile layouts must remain fully usable.
- Navigation must adapt to smaller screens.
- Text must remain readable without horizontal scrolling.
- Cards, tables, images, and other components must adapt to screen width.

## 9. Accessibility and Usability

- Use semantic HTML.
- Provide meaningful alternative text for informative images.
- Maintain sufficient text contrast.
- Make interactive elements identifiable and usable.
- Provide clear navigation and page titles.

## 10. Development Rules for AI Agents

Before making changes:

1. Read this AGENTS.md file.
2. Inspect the existing project structure.
3. Understand the current design and implementation.
4. Preserve existing working features unless changes are necessary.

When making changes:

- Follow the established visual and technical conventions.
- Avoid unnecessary rewrites.
- Keep components reusable where appropriate.
- Do not introduce broken links or missing assets.
- Do not silently remove existing content or functionality.
- Explain significant changes clearly.

After making changes:

- Check for broken links and missing assets where possible.
- Verify responsive behavior.
- Check that all affected pages still work.
- Report any unverified information or incomplete functionality.

## 11. Content and Asset Guidelines

- Use appropriate image formats and descriptive filenames.
- Respect copyright and image usage rights.
- Do not imply that fan-made graphics or materials are official.
- Keep content structured so it can be updated independently of the layout.

## 12. Project Priorities

Development priorities, in order:

1. Information architecture and complete website structure.
2. Consistent visual identity.
3. Accurate and well-organized archive content.
4. Responsive design.
5. Navigation and usability.
6. Performance and maintainability.

## 13. Deployment

- The final website must be deployable through GitHub Pages.
- Verify the deployment configuration before publishing.
- Test the public website after deployment.
- Ensure the repository contains the necessary project documentation.
